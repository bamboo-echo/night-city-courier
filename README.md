# 夜之城快递员 (NightCity Courier) · v2.0

一款基于 Java Swing 的赛博朋克风文字冒险 / 任务驱动小游戏。玩家扮演一名夜之城底层快递员，
在霓虹灯与废墟之间完成派送任务，靠随机事件、路线博弈、义体构筑与道德抉择，攒够 8000€ 离开这座城。

**零运行时依赖**：只用 JDK 17+ 自带的 Swing / NIO / 加密库，不引入任何第三方包，也不需要构建工具。

---

## 玩法简介

一单的完整流程：

```
看天气 → 挑订单 → 选路线（三选一）→ 逐段赶路（可能触发事件）→ 交货 / 砸单 → 结算 → 成长
```

- **任务**：普通件 / 黑市件 / 紧急件，叠加 16 种剧情变体（陷阱件、活体件、名人件、遗物件、
  竞速件、圈套件、救命件、错送件、告白件、证据件……）
- **随机事件**：16 类遭遇，从城警拦路、帮派围堵，到义体故障、无人机临检、地下电台、街头艺人、小孩扒手、旧相识、公司招聘
- **成长**：3 条属性线 + 8 项技能 + 11 件义体/消耗品 + 3 方派系声望
- **支线**：3 条剧情链共 12 拍，随机推进，不能主动刷
- **结局**：九道门 + 多结局分支，「传奇英雄」「平凡逃离」等，由你的关键抉择决定

## 核心设计：因果层

一份存档里，玩家会做几十个选择。如果这些选择只是各自结算完就消失，那游戏就是一串互不相关的小游戏。

v2.2 加了一层 **世界记忆（`core/Memory`）**：每个有道德或立场意义的选择写成一条事实（救过人、卖过器官、出卖过同行、放走过活体货物……），再由事实派生出**名声画像**。画像不是数值加成，而是**内容开关**，向下改写四层：

```
选择 ──► Memory 台账 ──► 名声画像 ──┬─► 事件池偏移   （你会遇到什么）
                                  ├─► NPC 口吻     （同一事件，开场不同）
                                  ├─► 支线触发     （做了什么，就走进哪条线）
                                  └─► 结局回顾     （逐条念出你做过的事）
```

具体到一条链：

1. 你在巷子里救下一个流血的人 → 记一条 `SAVED_LIFE`
2. 这条事实立刻推进**旧友线**第一拍（老K“顺路”叫你旧外号）
3. 继续行善、拒绝公司收买 → 画像从「无名之辈」变成「夜之城的圣人」
4. 从此**求救事件权重 +8**、**扒手权重 -4**、**城警权重 -2**
5. 同一个求救事件，开场从默认变成：“有人在喊救命。他看见你，像是看见了唯一能指望的东西。”
6. 结局时逐条念出：你救了一个人、你拒绝了公司的收买……最后给一句判词

反过来走另一条路：

1. 你把同行卖给公司 → `SOLD_OUT_COLLEAGUE`
2. 再塞两次钱给城警 → 画像变成「公司的人」
3. 从此**城警权重 -6**（警戒线会为你抬高），但**帮派遇到你会明显变多**
4. 求救的人看见你会压低声音；结局判词是“你有了工牌，也有了别人看你的眼神”

三条支线也不再靠掷骰：**放走活体货物/帮拾荒者/参加陌生人的婚礼** 走屋顶线，**听不明信号/拆炸弹** 走幽灵线，**救过人/给过钱/放过对手** 走旧友线。你做什么，就进哪条线。

### 第五层：具名人物关系

名声是「整座城怎么看你」，但真正让人记住一座城的是**具体的人**。v2.3 加了五个有名字、有态度、会再出现的人：

| 人物 | 他记得什么 | 关系好时 | 关系差时 |
|---|---|---|---|
| **老K** | 以前一起跑单的人，三年前消失 | 给你介绍一桩别人接不走的活儿 | 把你的行踪卖给了公司 |
| **小满** | 拾荒者网络里的孩子 | 在通风管里替你敲开封锁 | 屋顶的路对你关闭 |
| **格雷** | 公司的猎头，灰西装 | 给你稳定高价的长期单 | 开始派人盯你 |
| **薇** | 以前的相识，雨里认识的 | 给你留了钥匙和绷带 | 把烟按灭，转身走了 |
| **Doc** | 开义体诊所的老太太 | 补接口不收钱 | 今天不营业 |

**同一件事对不同的人意义完全不同**——这是关系的核心：

```
你把同行卖给公司
  └─ 格雷  +28  「他有业绩，你好用。」
  └─ 老K   -35  「那是我一起跑过单的人。」
  └─ 小满  -25  「他们说你卖过人。」
  └─ 薇      0  （她不认识那些人）
  └─ Doc    -8  「我这儿不收那种人的货。」
```

而且关系是**净值**，不是标签：放走活体货物给小满 +22，出卖同行给她 -25，
两件事会互相抵消，最终关系是 -3。她不会因为你做过一件好事就永远认你。

关系值同时决定**在路上遇见他们的频率**：关系越极端（极好或极坏）越容易碰见，
中间地带的人反而很少出现——跟你没关系的人不会总出现在你眼前。

结局会逐条念出「谁把你当朋友，谁把你当敌人」。

**三层记忆的关系**：

```
Memory   整座城怎么看你      →  事件池偏移、口吻、结局判词
Contacts 五个人各自怎么看你  →  专属遭遇、人物弧线、结局关系回顾
Storyline 你做过什么        →  支线推进
```

三者<b>刻意不同步</b>：你可以在全城面前是圣人，却欠着老K 一条命没还；
你可以在名声上是冷血动物，却让小满只认你一个人。

## v2.0 新增了什么

### 一、路线成为真正的选择

原版赶路只有「走 N 步」。现在每次接单会给出**三条路线**，分别在步数 / 风险 / 报酬 / 事件密度上取舍：

| 路线 | 特征 | 适合 |
|---|---|---|
| 公司天桥 | 极快，风险最高，报酬最高 | 赶时间且不怕事的赌徒 |
| 旧排水渠 | 极慢，几乎不遇正面冲突 | 残血、想活着回城 |
| 夜市外围 | 绕远，但报酬显著上浮 | 想加速攒钱 |
| 后巷穿行 / 高架桥下层 / 废弃地铁 / 直穿主干道 / 旧货运线 | 各种中间形态 | 看当时心情 |

系统保证每次给出的三条**必然分别覆盖「快 / 稳 / 赚」**，不会出现三条都是高危快线这种伪选择。

### 二、天气与时段

6 种天气 × 4 个时段 = 24 种环境组合，影响事件密度与报酬倍率：

- 血月：事件率 ×1.35，报酬 ×1.15
- 全城断电：事件率 ×0.85（摄像头瞎了），报酬 ×1.30
- 深夜：事件率上升，报酬也上升
- 凌晨：安静，但单子便宜

读环境做判断，而不是套一个固定最优解。

### 三、义体、背包与技能树

- **11 件物品**：5 件消耗品（急救针、战斗鸡尾酒、影子证件、信号干扰器、烟雾弹）+ 6 件义体
  （冷藏箱、幽灵协处理器、皮下装甲、涡轮套件、神经链路、黑冰破解器）
- **义体三槽**：装满必须卸下才能换，把「全买一遍」变成构筑选择
- **8 项技能、共 19 级**：潜行步法、银舌头、扳手直觉、街头之眼、铁胃、议价高手、最后一搏、网潜者
- **技能点不可重置**：跑偏了就是这一局的剧本

### 四、派系声望

城警 / 帮派 / 拾荒者三方独立声望（-100 ~ 100），**零和博弈**：

- 对某派系敌对 → 该派系事件变多，贿赂涨价 50%
- 同盟 → 事件减少，贿赂打七折
- 三方不可能同时讨好，长期立场成为策略

### 五、成就系统

24 个成就，覆盖三种互斥玩法路径：效率类（连成十单、单笔超千）、道德类（圣人与屠夫，只能二选一）、
猎奇类（通缉满级下完成一单、1 点血交货）。隐藏成就在解锁前只显示 `???`。

### 六、每日挑战

日期决定种子——**同一天开局的人面对同一套主线随机**（天气、时段、路线、事件抽取完全一致），
分数才有可比性。每天附带一条「城市规则」修正（酸雨封城 / 血月当空 / 断电之夜 / 涨价日……）。

```java
DailyChallenge.Spec spec = DailyChallenge.today();
// spec.seed()      → 当天的种子
// spec.headline()  → 今日规则说明
DailyChallenge.score(money, deliveries, failures, achievements);  // 统一算分
```

### 七、支线剧情链

三条线，每条 4 拍，共 12 拍。每完成一单约 28% 概率推进一拍——**不能主动刷**，只能一直在城里跑。

- **幽灵**：一个只通过通讯器出现的声音，最后你见到它的主人
- **屋顶**：拾荒者网络从戒备到接纳，最后给你一把用铜线拧成的钥匙
- **旧友**：一个不断「顺路」出现的老朋友，最后一次他真的需要你

### 八、界面重做：雨夜工业 HUD

旧界面是霓虹紫青 + 圆角 + 外发光 + 窗口抖动，属于千禧年那套廉价故障感。v2.0 整套换掉：

| 维度 | 旧 | 新 |
|---|---|---|
| 底色 | `#0A0A14` 蓝紫 | `#0B0D10` 冷灰近黑 |
| 强调色 | 青 + 洋红 + 紫，三色并用 | **单一琥珀 `#E8A33D`** |
| 圆角 | 8px 大圆角 | 2px，多数元素直接直角 |
| 装饰 | 外发光、玻璃感、窗口抖动 | 一像素细描边、四角刻线、点阵底纹 |
| 字体 | 单一黑体 | 中文黑体 + 等宽数字混排 |
| 布局 | 文本区 + 底部按钮 | 顶部状态条 + 左状态 / 中现场 / 右订单三栏 |

设计原则只有一条：**颜色越亮，信息越重要**。任何装饰元素都不允许亮过它要表达的内容。

界面全部自绘（`ui/UiKit` + `ui/Screens`），不依赖图片资源。因此可以在无显示环境下
把真实布局渲染成图片验证——见 [`preview/`](NightCityCourier/preview)：

```bash
java -Djava.awt.headless=true -cp out com.moji.NightCityCourier.ui.Preview preview
```

### 九、工程层

| 能力 | 实现 |
|---|---|
| 可复现随机 | `Rng`（SplitMix64，可种子化、可派生、可洗牌）替代全局 `Random` |
| 分级日志 | `GameLog`（TRACE/DEBUG/INFO/WARN/ERROR + 可插拔 sink + 文件落盘） |
| 存档 v3 | `SaveCodec`：CRC32 + SHA-256 双校验 + 显式长度 + 键值转义 |
| 多槽位 | `SaveStore`：原子写（tmp + ATOMIC_MOVE）、备份轮转（3 份）、损坏隔离 |
| 旧档兼容 | v2 存档自动识别并迁移为 v3，不会因为升级而丢档 |
| 成长聚合 | `CourierProfile`：背包/技能/派系/成就/统计/天气一体化序列化 |

## 运行

需要 **JDK 17 或更高版本**。

```bash
cd NightCityCourier

# Windows
.\build.ps1 -Run

# macOS / Linux
./build.sh --run
```

手动编译：

```bash
javac -encoding UTF-8 -d out src/com/moji/NightCityCourier/*.java src/com/moji/NightCityCourier/core/*.java
java -cp out com.moji.NightCityCourier.Main
```

入口类：`com.moji.NightCityCourier.Main`

启动时可选择 **普通局** 或 **每日挑战**：每日挑战用日期派生种子，同一天所有玩家面对
同一套天气、路线与事件抽取，分数可比。

> Linux 无图形环境下会抛 `HeadlessException`——这是 Swing 游戏，需要显示设备。测试不受影响。

## 存档

两套存档**并列存在、互不影响**，都在 `~/.nightcity/`：

| 文件 | 格式 | 内容 |
|---|---|---|
| `save.dat` | v2（原格式，保持不变） | 核心数值：钱、血、等级、通缉、声望、回响石 |
| `profile.dat` | v3（新增） | 成长层：背包、义体、技能、派系、成就、统计 |

v3 格式：

```
NCCv3
version=3
created=1712345678901
payload-len=1234
crc32=1a2b3c4d
sha256=...(64 hex)
--
key=value
...
```

设计取舍：

- **双校验**：CRC32 做廉价的完整性判断，SHA-256 做内容摘要，配合 `payload-len` 可以区分
  「被截断」和「被篡改」，而不是笼统报一句「存档损坏」；
- **键值转义**：`\` `\n` `\r` `=` 四个转义，值里出现换行也不会错位；
- **原子写**：先写 `.tmp` 再 `ATOMIC_MOVE`，断电不会留下半个存档；
- **备份轮转**：`main.dat.bak1` ~ `.bak3`，读取失败时自动向上回溯；
- **损坏不丢档**：问题文件改名为 `.corrupt-<时间戳>` 保留，绝不静默删除。

## 平衡配置

`GameConfig` 是所有可调参数的唯一入口：

| 常量 | 作用 |
|---|---|
| `WIN_TARGET` | 逃离夜之城所需金额（默认 8000，演示可调小压缩流程） |
| `HEALTH_CRITICAL` | 致命伤阈值（影响赌局复仇与结局） |
| `REPUTATION_VETERAN` / `REPUTATION_BOTTOM` | 老手 / 底层判定 |
| `*_WEIGHT` | 12 类事件的抽取权重 |
| `VARIANT_CHANCE` | 任务出现特殊变体的概率 |

游戏内的金额文案全部从 `WIN_TARGET` 读取，判定阈值同理集中在 `GameConfig`，
改一个数字全局生效，不需要同步修改字符串。

成长层的数值集中在各自枚举里（`Item` 价格、`SkillTree.Skill` 效果、`WeatherSystem.Weather` 倍率、
`RouteSystem.POOL` 路线参数），调平衡只改一处。

## 跨平台

游戏可在 Windows / macOS / Linux 上运行。中文字体族与 emoji 字体族按平台优先顺序自动探测
（雅黑 → 苹方 → 思源 → 文泉驿等 / Segoe UI Emoji → Apple Color Emoji → Noto Color Emoji），
未命中时退回 Swing 逻辑字体 `SansSerif`，不会因缺少字体而崩溃或乱码。

解析逻辑在 `GameConfig.resolveFontFamily()` / `resolveEmojiFontFamily()`，字体族常量
`FONT_FAMILY` / `EMOJI_FONT_FAMILY` 供各界面类共用。

存档路径基于 `System.getProperty("user.home")`，同样跨平台；槽位名会做字符白名单清洗，
防止路径穿越。

## 设计说明：为什么这么改

原版的问题不在于「内容少」，而在于**决策密度低**——每一单的最优解是固定的：
能打得过就打，打不过就贿赂，血少了就治疗。玩家没有真正需要权衡的地方。

v2.0 的每一处新增都在制造「两条都对，但只能选一条」：

- 路线：快 vs 稳 vs 赚
- 义体：三槽，装什么就是什么流派
- 技能：点数不可重置，跑偏了认命
- 派系：三方零和，讨好一方就得罪一方
- 天气：同一个选择在不同环境下收益完全不同
- 消耗品 vs 义体：短期保险还是长期薄利

工程上则守住一条底线：**所有新系统必须能被无头测试**。因此新增逻辑全部放在 `core/` 包，
不依赖 Swing、不依赖静态全局状态、随机源可注入。`GameController` 只负责编排，不做计算。
